# RMX5303 — ReLite v0.2.0 benchmark report

Real measurements from the same physical RMX5303EEA unit used for
v0.1.0. This pass focused on correctness/security/multi-device-safety
fixes to the CLI engine and a `WorkspaceController` domain-layer
foundation for ReLite Home, not new debloat targets — the device-level
profile numbers below are unchanged from v0.1.0 (no packages were added
to or removed from any profile's action map this pass; see
`devices/realme/RMX5303/packages.yaml`'s only content change, a reason-
text correction with no effect on behavior). Only the ReLite Home vs.
stock launcher comparison was re-measured, per the explicit requirement
to publish current numbers rather than retain old ones.

## ReLite Home vs. the stock launcher

| Metric | Stock launcher | ReLite Home v0.2.0 | Change |
|---|---:|---:|---:|
| Settled PSS (median of 3 runs, 45s post-cold-start) | 123,310 kB | 53,957 kB | **−56.2%** |

Full per-run data: `benchmarks/results/RMX5303/relite-home-vs-stock-launcher-v0.2.0.json`.
Same settle-time methodology as v0.1.0 (`benchmarks/methodology.md`).

**Compared to v0.1.0's measurement** (109,181 kB stock / 74,817 kB
ReLite Home / −31.5%), both sides moved this session: the stock
launcher's own settled PSS is *higher* now (109,181 → 123,310 kB, +13%)
and ReLite Home's is *lower* (74,817 → 53,957 kB, −28%). Neither number
was cherry-picked — both are tight, low-variance 3-run medians (stock:
123,282–123,559 kB; ReLite Home: 53,450–54,144 kB), same as v0.1.0's
methodology. But this is **not a controlled A/B**: the two sessions ran
days apart, and the stock launcher's higher PSS most plausibly reflects
normal background-state drift on a live system (Play Store/GMS cache,
notification/shortcut state, etc.) that ReLite has no influence over and
did not attempt to measure in isolation. ReLite Home's own reduction is
more directly attributable to this pass's actual changes — the four
independent per-screen `IconCache` instances from v0.1.0 collapsed into
one process-wide, budget-bounded cache, plus the `MainActivity.onDestroy`
lifecycle fix removing a listener re-registration path — but this
session did not bisect commit-by-commit to isolate exactly how much of
the drop each fix contributed. Report both deltas as measured; don't
read the widened gap as proof ReLite Home is now "56% better" in some
durable sense beyond what these two specific sessions show.

## What this report does not claim

- No re-run of the four-profile cold-start comparison (unchanged inputs
  this pass — see above).
- No boot-time comparison, frame-timing/jank data for the app drawer, or
  multi-session statistical confidence interval — same gaps as v0.1.0,
  still not addressed.
- No isolation of which specific v0.2.0 change (shared icon cache vs.
  lifecycle fix vs. session-to-session drift) produced how much of the
  ReLite Home PSS delta.
- No claim about battery/idle power draw.
- No claim about the interactive editable-workspace features
  (drag-to-reposition, dock editing, folder-editing UI, full widget
  add-flow) — those are domain-logic-only in `WorkspaceController` this
  release and were not exercised in this benchmark or on-device.
