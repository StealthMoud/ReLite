# ReLite Home v0.5.0 — scoped stress pass (RMX5303)

Run via `scripts/stress-relite-home.sh`, physical RMX5303, 2026-08-10.

This is **not** the full multi-hour stress campaign master plan sections
194-209 describe (200 Home swipes, 100 folder open/close cycles, a full
5-minute idle-CPU sample, per-surface jank measurement, a fresh controlled
A/B against the stock launcher). It is a real, scoped pass — every number
below is from an actual `adb`/`dumpsys` run against the physical device,
not estimated or carried over from a prior version. See CHANGELOG's Known
gaps for what the full campaign still requires.

## What ran

- 3× cold start (`am force-stop` + `am start -W`)
- `dumpsys meminfo` before stress, after stress, after a 60s settle
- 300 randomized `input tap`/`input swipe` events against the whole screen
  (not `monkey -p` — see below)
- A logcat scan for `FATAL EXCEPTION` / `ANR` attributable to `io.relite.home`
  specifically (filtered on the `Process: io.relite.home` line, not just the
  exception banner, which doesn't name a package)

## Real finding: `monkey -p io.relite.home` cannot be used against this app

`monkey`'s package-scoped mode resolves its target via a `CATEGORY_LAUNCHER`
intent. ReLite Home's `MainActivity` deliberately has no `CATEGORY_LAUNCHER`
category (section 46, v0.4.1) — otherwise it would list itself in its own
app drawer. Running `monkey -p io.relite.home` against a real device fails
outright: `** No activities found to run, monkey aborted.` — a genuine,
reproducible tooling gap this pass uncovered, not a simulated result. Worked
around by injecting raw `input tap`/`input swipe` events directly instead
(package-scoped only in the sense that ReLite Home was already foregrounded
first; a stray tap can still legitimately navigate to a system surface ReLite
launches, e.g. App info or the wallpaper picker — see below).

## Results

Cold start (`TotalTime` from `am start -W`, three consecutive cold launches):

```
794ms, 822ms, 767ms
```

No historical comparison is claimed here — v0.4.1's README figures were not
re-measured this pass and are not carried forward as if they still apply to
v0.5.0's build.

`dumpsys meminfo` TOTAL PSS:

```
cold (3s after launch):        60,816 KB / RSS 188,180 KB / swap 325 KB
after 300-event input stress:  52,787 KB / RSS 145,640 KB / swap 36,766 KB
after 60s idle settle:         52,703 KB / RSS 154,760 KB / swap 27,577 KB
```

The post-stress figure is lower than cold, not higher — expected here, not
a sign of a leak: the 300-event random input run ended with a tap that
navigated out of ReLite Home into an OEM system surface
(`com.coloros.phonemanager/.FakeActivity`, confirmed via
`dumpsys window | grep mCurrentFocus`), so these two samples aren't an
apples-to-apples "same foreground state" comparison. No PSS growth trend
was observed across the samples that were foreground-comparable.

Crash/ANR scan: **empty** — no `FATAL EXCEPTION` with `Process: io.relite.home`
and no `ANR in io.relite.home` in the logcat buffer across this pass.

Idle CPU sample: the `top`-based capture in the script did not reliably
parse into per-process rows on this device/Android build — recorded as
inconclusive rather than reporting a number, instead of fabricating one.

## Known gaps in this pass

- No jank/frame-timing measurement (Home, Apps, folders, edit mode).
- No 5-minute idle CPU figure (the script's 60s attempt didn't parse).
- No controlled A/B against the stock launcher for v0.5.0 specifically.
- No folder/widget/theme/grid-migration-specific stress loops (only
  generic whole-screen random input).
- Single device, single run — not repeated for variance.
