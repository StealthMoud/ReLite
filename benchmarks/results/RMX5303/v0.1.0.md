# RMX5303 — ReLite v0.1.0 benchmark report

Real measurements from a physical RMX5303EEA unit. No fabricated or
extrapolated numbers — see `benchmarks/methodology.md` for exactly how
each figure was produced, including two real measurement-methodology
bugs found and fixed while producing this report (`am start -W`
reporting `TotalTime: 0` for same-task "warm starts", and `dumpsys
meminfo` PSS needing a verified settle time before it means anything).

## Profiles: stock vs. safe vs. performance vs. maximum

| Metric | stock | safe | performance | maximum |
|---|---:|---:|---:|---:|
| Enabled packages | 400 | 397 | 390 | 385 |
| Disabled packages | 2 | 5 | 12 | 17 |
| Settings cold start (median) | 1177 ms | 1170 ms | 544 ms | 583 ms |
| Camera cold start (median) | 724 ms | 629 ms | 612 ms | 596 ms |
| MemAvailable | 5,176,736 kB | 5,359,204 kB | 5,252,636 kB | 5,132,800 kB |

**Recommended profile: `performance`.** All four profiles were applied
and verified stable on this unit (boot completes, SystemUI/Settings/
Camera/telephony/Bluetooth intact, no crashes in logcat) across two
independent full validation passes, including a complete
stock→performance→restore→performance round-trip that produced a
byte-for-byte identical package set both times (see
`devices/realme/RMX5303/findings.md`).

**MemAvailable is not monotonic across profiles** (`maximum` shows the
lowest value here, not the highest) — this reflects normal single-pass
background-cache/measurement noise on a live system, not `maximum`
performing worse. Package-count reduction and cold-start latency are the
metrics with a clear, repeatable signal in this data; MemAvailable
deltas of this size should not be read as a ranking between profiles.

Cold-start improvements are real and repeatable within each run's 5
samples (medians reported, not best-of), but reflect a single
benchmarking session — see `benchmarks/methodology.md` for what would be
needed to strengthen this into a multi-session statistical claim.

## ReLite Home vs. the stock launcher

| Metric | Stock launcher | ReLite Home | Change |
|---|---:|---:|---:|
| Settled PSS (median of 3 runs, 45s post-cold-start) | 109,181 kB | 74,817 kB | **−31.5%** |

Full per-run data: `benchmarks/results/RMX5303/relite-home-vs-stock-launcher.json`.

This number was revalidated after fixing a real regression found during
profiling: an early build of `IconCache` cached full-resolution
`AdaptiveIconDrawable`s bounded only by entry count, not memory, which
pushed Native Heap to ~136 MB. Fixed to render each icon once into a
bitmap sized to its actual display size, bounded by a real ~6 MB byte
budget (`android/relite-home/.../util/IconCache.kt`,
`BoundedByteCache.kt`). The 31.5% figure is measured *after* that fix,
using a settle time verified via a decay curve rather than assumed — see
methodology.md for why an earlier, less careful measurement pass
produced a misleadingly different (and, at one point, misleadingly
worse) number from restarting the process repeatedly at too short a
fixed delay.

## What this report does not claim

- No boot-time comparison across profiles — not run in this pass (see
  `benchmarks/scripts/boot_benchmark.sh` for the tooling, ready but
  unused this session).
- No frame-timing/jank data for ReLite Home's app drawer scroll — not
  yet collected (`benchmarks/scripts/frame_stats.sh` is ready).
- No multi-session statistical confidence interval — all figures are
  from single sessions with multiple in-session runs (5 for cold starts,
  3 for PSS), per `benchmarks/methodology.md`.
- No claim about battery/idle power draw.
